# Donation Domain

```text
Supporter
  ↓
Wallet
  ↓
Donation Order
  ↓
Donation Event
  ↓
Creator
```

Platform-specific behavior is handled through adapters.

```text
Donation Core
    ↓
PlatformAdapter
    ├── YouTube
    ├── FlexTV
    ├── SOOP
    └── CHZZK
```

## 퀘스트 후원 결과 (2026-10-04 결정)

- 퀘스트 후원은 보낼 때 성공 보상 금액 전부를 FN에서 차감해 보관한다.
- 결과를 정할 수 있는 사람 (위젯 설정의 결정 권한 표): 보낸 후원자는 항상(성공 · 실패), 크리에이터는 후원자가 "크리에이터 성공 결정"을 켠 경우에만(성공 · 실패). **취소**는 크리에이터만 언제든 할 수 있다.
- **성공**: 금액은 크리에이터에게 간다.
- **실패**: 후원한 FN을 후원자에게 **전액 환불**한다. 실패 금액 · 실패 패널티는 없다.
- **취소** (크리에이터): 실패와 같이 **전액 환불**한다. 취소 금액 · 취소 패널티는 없다. 상태 표기 "취소 · 환불".
- **제한 시간**: 지나도 자동으로 끝내지 않는다. 누군가 결과를 정할 때까지 진행 중으로 남고, 퀘스트 위젯에는 "시간 초과 · 결과 대기"로 보인다.
- 결과는 한 번만 정한다. 같은 결과를 다시 보내면 첫 결과를 그대로 돌려주고(재시도 안전), 다른 결과는 거절한다. 환불은 한 번만 일어난다.
- **진행 중에는 탈퇴 불가 (2026-10-08 결정)**: 진행 중인 퀘스트를 보낸 후원자와, 그 퀘스트가 온 채널의 크리에이터는 결과가 정해질 때까지 탈퇴할 수 없다(`QUEST_PENDING`, 서버가 비밀번호 확인 전후로 확인). 그래서 실패 · 취소 환불은 항상 보낸 계정으로 가고, 탈퇴 뒤 재가입한 새 계정으로 가지 않는다. 크리에이터는 취소로 언제든 끝낼 수 있다. 자세한 내용은 [wallet.md](wallet.md) 회원 탈퇴.
- 기록: 결정 시각 · 결정한 쪽(크리에이터 / 후원자) · 환불 금액. 후원자 지갑에는 해당 후원이 "환불완료"가 되고 FN 내역에 환불 줄과 알림(실패 / 취소 문구)이 생긴다.
- **보관 중 집계 (구현)**: 진행 중인 퀘스트의 후원 내역은 "처리중"(PROCESSING)이고, 성공하면 "완료"가 된다. 성공 전에는 크리에이터 몫으로 세지 않는다 — 크루 점수판 · 서브 점수판 · 배틀 · 직급 보너스 · 멤버 순위, 방송 후원 리스트, 후원 위젯(목표 · 누적 · 랭킹 · 수단별 보드), 후원자 등급 · 칭호, 채널 월간 순위, 관리자 집계 모두. 방송 알림("퀘스트 도착")과 퀘스트 위젯은 보낼 때 바로 나온다.
- 성공하면 그 시각에 크루 쪽에 반영한다(멤버 지정 퀘스트는 멤버 점수 · 순위, 지금 진행 중인 배틀에도 들어감). 멤버를 지정하지 않은 퀘스트는 보낼 때 진행 중이던 방송이 아직 진행 중일 때만 그 방송의 후원 리스트에 들어가고, 그 방송이 끝난 뒤 성공하면 후원 리스트에는 넣지 않는다(끝난 점수판은 확정). 받은 후원 › 크루 후원에는 진행 중 · 환불된 멤버 퀘스트도 상태와 함께 보인다.
- **성공한 날 기준 집계 (2026-10-08 결정 "퀘스트는 성공한 날 기준 집계")**: 성공한 퀘스트는 보낸 날이 아니라 성공한 날에 수령액으로 센다 — 후원 리스트 요약(총 수령액 · 오늘 · 이번 주) · 기간 필터 · 연도 · CSV(퀘스트는 "성공일시" 열 추가)와 후원 위젯(목표 · 누적 · 랭킹 · 수단별 보드, 알림의 `questSucceededAt`). 목록의 후원일시는 보낸 시각 그대로이고 성공한 퀘스트는 상태 옆에 성공 시각을 보여 준다. 진행 중 · 환불된 퀘스트는 보낸 시각 기준. 후원자 쪽 집계(FN 내역 · 등급 · 채널 월간 순위)는 바꾸지 않았다.

## 미니 후원 금액 (2026-10-09 결정)

- 미니 후원은 **1,000 FN 미만** — 100 ~ 999 FN(`MINI_MAX_FN`, 후원 카탈로그 `maxAmount.MINI`). 최소 100 FN은 디자인 값 그대로다.
- 서버(Donation Core)가 범위를 확인하고, 벗어나면 차감하지 않고 거절한다(`INVALID`). 1,000 FN 이상은 일반 후원으로 보낸다.
- 후원 패널: 금액 칸 안내 "100 ~ 999 FN", 999 FN을 넘기면 "미니 후원은 999 FN까지예요. 1,000 FN부터는 일반 후원으로 보내 주세요"를 보여 주고 보내지 않는다.
- 미니후원 위젯의 최소 표시 금액도 0 ~ 999 FN이다(그보다 크면 아무것도 뜨지 않으므로 저장할 때 거절).

## 가격 확인 · 문구 검사 · 재시도 (구현)

- 시그니처 이미지가 라이브러리에서 지워지면 후원 패널 · 알림 · 벽지 모두 첫 기본 이미지로 보인다 — 시그니처 후원과 금액 매칭된 일반 후원 둘 다(`signatureImageFor`).
- 시그니처 · 위시 · 뽑기는 가격을 서버가 정한다. 후원 패널은 보여 준 가격(`expectedAmount`)을 함께 보내고, 그 사이 크리에이터가 가격을 바꿨으면 차감하지 않고 "가격이 바뀜"(지금 가격)을 돌려준다. 같은 요청을 다시 보내면 같은 답을 받는다(가격도 요청의 일부).
- 뽑기 기록 · 알림 메시지의 금액은 실제로 차감한 금액이다.
- 상품소진형 재고: 설정 화면을 연 뒤에 뽑힌 수량은 저장해도 되살아나지 않는다(서버가 상품별 뽑힌 수를 세고, 저장할 때 그 사이 뽑힌 만큼 뺀다).
- 후원자가 쓴 글(일반 메시지 · 미니 텍스트 · 시그니처 / 위시 메시지 · 퀘스트 / 그림 제목)에 플랫폼 금지어가 있으면 차감 전에 거절한다("사용할 수 없는 단어가 포함되어 있어요.").
- 크리에이터의 금지어(후원 페이지 설정 › 대체 메시지 표시 설정): 화면 문구대로 금지어가 들어간 후원은 방송 알림(TTS 포함)에서 대체 메시지로 보인다(닉네임 · 텍스트 내용 스위치별). 결제와 기록은 원래 글 그대로. 2026-10-07 결정: 방송에 나가는 퀘스트 위젯 제목과 그림후원 오버레이(닉네임 · 그림 제목)에도 같은 대체 규칙(금지어 · 후원 필터링)을 적용한다. 스튜디오의 퀘스트 · 그림 목록은 원래 글을 보여 준다. 테스트 그림은 대상이 아니다.
- 룰렛 · 뽑기 오버레이(진행 화면, 뽑기 메시지, 당첨 리스트)의 후원자 이름도 같은 대체 규칙을 적용한 이름이다. Donation Core가 후원 시점에 `shownOnStream`으로 한 번 계산해 넘기고, 리모컨과 기록은 원래 이름을 쓴다.
- 그림후원 이미지는 PNG data URL이어야 하고, 서버가 base64를 디코딩한 바이트의 PNG 시그니처까지 확인한다(접두어만으로는 통과하지 않음).
- **대체 메시지가 비어 있을 때 (2026-10-06 결정 "기본 문구로 표시")**: 메시지는 기본 문구 "(금지어가 포함된 메시지예요)"(`DEFAULT_REPLACEMENT_MESSAGE`), 닉네임은 "익명"으로 보인다. 설정 칸 아래에 같은 안내를 보여 준다.
- **후원 필터링 탭 (2026-10-06 결정 "대체 메시지로 바꿔 표시")**: 걸리는 후원도 거절하지 않고 그대로 처리한다(결제 · 기록 · 집계는 원래 글). 방송 알림과 TTS에서만 **메시지**가 대체 메시지(비어 있으면 기본 문구)로 바뀐다. 화면 문구가 "도네이션 내용"이라 닉네임에는 적용하지 않고, 텍스트 내용 스위치와 상관없이 필터링 탭 설정대로 적용한다. 서버의 `shownOnStream`(`donationPageCore.ts`)에서 처리하므로 알림을 띄우는 모든 썸네이션 후원에 적용된다. 테스트 후원 · 플랫폼 후원(후원 연동 · 계좌 후원, EXTERNAL)은 금지어와 같이 적용하지 않는다(화면에 통합 후원 언급 없음).
  - 커스텀 블랙리스트 단어: 금지어와 같이 대소문자 무시 · 포함 여부.
  - 특수 문자/도배 차단(화면에 기준이 없어 좁게 정한 가정, TBD: 실제 메시지로 조정): 같은 글자 10번 이상 연속(예: "ㅋ" 10개, "!" 10개), 또는 공백이 아닌 글자로 시작하는 2~5글자 묶음이 5번 이상 연속(예: "사랑해" 5번), 또는 글자 · 숫자 · 공백이 아닌 문자(기호 · 이모지 · 결합 문자)가 10개 이상이면서 공백 제외 글자의 절반 넘음. 메시지 하나씩 판단하고, 여러 번 후원하는 것은 도배로 보지 않는다.
  - 비속어 필터 강도: 비속어 사전은 아직 없다(제공처 TBD). 지금은 플랫폼 금지어(`MOCK_FORBIDDEN_WORDS`)만 본다 — 사용 안 함 = 검사 없음, 보통 = 쓴 그대로(대소문자 무시), 매우 높음 = 공백 · 기호로 띄워 쓴 경우도("운 영 자"). 같은 단어를 그대로 쓴 후원은 차감 전에 이미 거절되므로, 실제 사전이 생길 때까지 보통은 사실상 걸리는 후원이 없다. TBD: 실제 사전과 강도별 범위.
- 결과를 받지 못한 후원(네트워크 오류 · 처리 중)은 다음 "후원하기"에서 같은 요청 · 같은 키로 먼저 결과를 확인한다. 완료됐으면 완료 화면을 보여 주고 고친 내용은 보내지 않으며, 실패가 확정된 경우에만 새 요청을 보낸다. 서버는 같은 키의 재시도에 카탈로그가 바뀌었어도 첫 답을 돌려준다.

## 후원자 표시 · 별명 (구현)

- **프로필 숨기기**: 후원 기록에 `hideProfile`을 남기고, 공개 집계(채널 월간 순위)에서 회원 닉네임 줄에 넣지 않는다. 방송 알림에는 "익명"으로 보인다. **2026-10-08 결정 "명예의 전당·랭킹에서 익명 제외"**: 명예의 전당 리더보드 · 실시간 랭킹(`hallOfFame/supporterRanking.rankSupporters`), 내 후원 랭킹(`supporter/ranking`), 방송 후원랭킹 위젯도 숨긴 후원을 빼고 집계한다. 숨긴 후원을 별도 "익명" 줄로 보여 줄지는 TBD. **2026-10-09 결정**: 숨긴 후원은 그 크리에이터의 크리에이터 칭호(새싹 팬 ~ 왕관 팬)에도, 보낼 때 고른 별명(또는 대표 · 기본 별명)의 별명 관리 누적 금액 · 횟수에도 들어가지 않는다(`donate.ts`는 숨긴 후원을 별명에 연결하지 않고, `identityCore.computeIdentity`는 숨긴 후원을 별명 합계에서 뺀다). 누적 등급 · 활동 등급에는 그대로 들어간다(`docs/domains/supporter.md`).
- **대체된 닉네임의 배지 (2026-10-09 결정)**: 대체 메시지 표시 설정(닉네임)이 이름을 바꾼 알림 — 대체 메시지가 비어 "익명"이 된 경우와 대체 메시지로 바뀐 경우 모두 — 에는 등급 · 칭호 배지를 붙이지 않는다(`alertCore.enqueueDonationAlert`). 배지는 대체로 가린 후원자의 것이기 때문. OBS 후원 알림은 알림에 저장된 배지만 그리므로 다시 보내기 사본도 같다. 후원 확인 창의 알림 미리보기는 크리에이터의 금지어를 후원자에게 보이지 않으려고 대체 전 이름 · 배지를 그대로 보여 준다(2026-10-09 결정으로 유지).
- **후원랭킹 위젯**: 표시 이름이 아니라 알림의 `donorKey`로 묶고 가장 최근 이름을 보여 준다. 키는 채널별 HMAC(회원 id가 아님, 오버레이는 공개)이고 숨긴 프로필은 키가 없어 순위에서 빠진다. 키가 없는 예전 · 시드 알림만 이름으로 묶는다. 그래서 다른 후원자의 이름을 별명으로 써도 그 사람 줄에 합쳐지지 않는다.
- **대체된 닉네임과 후원랭킹 (2026-10-09 결정)**: 대체 메시지 표시 설정(닉네임)이 이름을 바꾼 알림 — "익명"(대체 메시지가 빈 경우)이든 크리에이터가 정한 대체 메시지든 — 은 숨긴 프로필처럼 후원랭킹 위젯에서 뺀다. 같은 `donorKey`의 줄에 합쳐지지도, 그 줄 이름을 바꾸지도, 따로 줄이 생기지도 않는다. 알림을 큐에 넣을 때 그때의 금지어로 `nameReplaced`를 저장하므로(`alertCore.enqueueDonationAlert`), 나중에 금지어를 바꿔도 지난 알림이 다시 들어가거나 빠지지 않는다. 다시 보내기 사본은 원래부터 집계하지 않는다. 다른 방송 보드: 크루 후원 순위는 줄이 크루 멤버(이름은 크루 설정)라 후원자 이름이 줄에 들어가지 않고, 수단별 보드는 줄이 결제 수단이라 이런 후원도 "썸네이션 FN" 건수 · 합계에 그대로 들어간다(숨긴 후원과 같음). 목표 · 누적도 합계라 그대로다. 명예의 전당 · 내 후원 랭킹 · 채널 월간 순위는 방송 화면이 아니고 알림을 읽지 않는다(회원 닉네임으로 집계). **2026-10-09 결정**: 이 세 순위에는 크리에이터의 대체 메시지 · 금지어 규칙을 적용하지 않는다(동작 변경 없음). 줄 이름이 회원 닉네임이고 닉네임은 가입할 때 검사하며, 익명 후원은 이미 빠진다.
- **크루 방송 기록의 이름 (2026-10-09 결정)**: 크루 방송 후원 리스트 항목과 멤버 지정 기록(`crewCore.recordBroadcastDonation` · `recordAttribution`)은 보낸 이름(`donor`)과 함께 방송에 나갈 이름(`shownDonor`, 대체 메시지 규칙을 거친 "익명" 또는 대체 문구)을 저장한다. `shownDonor`는 후원을 보낼 때(알림과 같은 때) 정해지고 — 퀘스트는 보낼 때 정해 두었다가 성공할 때 기록에 넣는다 — 나중에 금지어를 바꿔도 다시 계산하지 않는다. 방송에 나가는 화면(OBS)은 `shownDonor`를, 크리에이터만 보는 방송 운영 후원 리스트와 받은 후원 › 크루 후원은 `donor`를 쓴다. 지금 OBS 크루 화면(점수판 · 랭크업 · 배틀 · 강탈 · 서브 점수판 · 시나리오)과 후원 위젯 크루 순위는 멤버 이름만 보여서 화면이 바뀌지는 않는다. 플랫폼 후원 · 계좌 후원 · 시뮬 후원은 알림에도 대체 규칙을 쓰지 않으므로 `shownDonor`가 보낸 이름과 같다.
- **별명 규칙**: "익명"(숨긴 프로필 표기)은 별명 · 회원 닉네임으로 쓸 수 없다. 회원 닉네임은 기본 별명이라 가입 · 마이페이지 변경 때도 같은 규칙(익명 · 금지어 · 다른 회원 닉네임 · 채널명 불가)을 서버에서 검사한다(`account/nicknameRules.ts`). **2026-10-08 결정 "다른 회원 닉네임·채널명 금지"**: 별명은 다른 회원의 닉네임이나 채널명과 같을 수 없다(앞뒤 공백 제거, 대소문자 무시; 별명 추가 · 이름 변경 때 서버에서 검사, "다른 회원이나 채널이 쓰는 이름은 별명으로 쓸 수 없어요."). 그 밖에는 내 별명 목록 안에서만 겹치지 않으면 된다(다른 회원의 별명과 같아도 됨).
- **후원 닉네임 변경 (후원 페이지 설정)**: 꺼져 있으면 고른 별명(기본으로 정한 별명 포함)은 무시하고 회원 닉네임으로 보낸다. 후원 패널의 별명 선택과 알림 미리보기도 회원 닉네임만 보여 준다. 랭킹 공개 · 후원 내역 공개 · 커스텀 사운드 공개 옵션은 아직 TBD.
- **재시도 키 · 요청 id는 회원별**: 후원 · FN 충전 · 플랫폼 후원(SOOP · FlexTV)의 Idempotency-Key, 1:1 문의 · 채널 글 · 이미지/사운드 라이브러리 업로드의 `requestId`는 회원 id와 묶어 저장한다(`lib/records.ts` `memberKeyOf`). 다른 회원이 같은 값을 보내도 그 회원의 결과를 돌려주거나 충돌로 막지 않고, 같은 회원의 재시도는 처음 결과를 받는다. 재가입하면 탈퇴한 계정의 키는 그 계정(`…-wN`)으로 옮겨져 새 계정의 요청에 답하지 않는다. 플랫폼 어댑터에는 회원의 키를 그대로 보내지 않고, 회원 id와 회원의 키로 서버 비밀값을 써서 만든 키(`pk-` + HMAC, `services/platformDonation/platformKey.ts`, 서버 전용)를 보낸다 — 같은 회원 · 같은 키면 같은 값이라 재시도가 플랫폼에서도 같은 요청이고, 다른 회원이면 다른 값이며, 회원 id나 원래 키를 거꾸로 알아낼 수 없다. 거래에 저장해 두고 결과 확인 조회도 이 키로 한다.
