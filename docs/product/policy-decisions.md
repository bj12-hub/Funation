# 정책 결정 목록 — StreamDonate 남은 항목

2026-10-24 작성. [streamdonate-reference.md](../research/streamdonate-reference.md)의 P2 · P3 개발 항목은 모두 구현했고(일부 mock),
남은 여섯 항목은 **돈이 움직이거나 돈의 성격을 바꾸는 기능**이라 만들지 않았습니다(CLAUDE.md §7 · §14: 정산 · 수수료 · 환불 같은
규칙을 지어내지 않음). 이 문서는 각 항목을 만들기 전에 **누가 무엇을 정해야 하는지**를 모은 것입니다. 값(비율 · 금액 · 기간)은
제안하지 않고, 고를 수 있는 선택지와 그 선택이 시스템에 주는 영향만 적습니다.

- 표시: **[제품]** 제품 결정 · **[재무]** 재무 · 세무 · **[법무]** 법률 검토 · **[운영]** 운영 정책
- "StreamDonate에서는"은 조사(보기만 함, 2026-10-23) 때 확인한 범위입니다. 메뉴 · 설정 이름만 보고 동작을 확인하지 못한 항목은
  그렇게 적었습니다 — 그 항목은 **정의부터** 정해야 합니다.

## 1. 외부 정산 연동

**지금**: 정산은 크리에이터 신청 → 운영자 심사 · 승인 → 운영자가 이체 후 "지급 완료" 기록(참조번호). 외부로 나가는 정산 데이터 ·
지급 연동은 없습니다. 크루는 멤버별 점수 · 기여도만 있고 **멤버에게 돈을 나누는 규칙은 TBD**입니다(route-map `/creator/crew`).

**StreamDonate에서는**: 관리 › 설정에 "외부 정산 연동" 이름만 확인 — 무엇과 연동하는지는 보지 못했습니다.

**정해야 할 것**

1. **[제품] 정의** — 무엇을 이 이름으로 부를지(여럿일 수 있음):
   - (a) **크루 멤버 분배**: 크루 방송 수익을 멤버에게 나누는 것
   - (b) **정산 데이터 내보내기**: 정산 · 지급 · 후원 원장을 회계 프로그램 · 세무 대리인 · 외부 정산 서비스로 보내는 것
   - (c) **지급 대행 연동**: 운영자의 수동 이체 대신 지급 대행사(펌뱅킹 등)로 자동 이체
2. (a)를 한다면
   - [제품] 분배 기준 — 멤버 지정 후원 금액 / 기여도 점수 / 고정 비율 / 크루장이 직접 입력
   - [제품] [재무] 받는 사람 — 멤버마다 Ssumnation 계정 · 정산 정보가 필요한지, 크루장이 받아 직접 나누는지(그러면 플랫폼 밖 거래)
   - [재무] 세금 주체 — 누가 원천징수 대상인지(C5)
   - [운영] 분배 시점(방송 회차 · 월), 멤버 탈퇴 · 정지 · 이적 중의 몫, 분배 다툼 처리
3. (b)를 한다면
   - [제품] 내보낼 데이터 · 형식(CSV 내려받기 / API) · 주기
   - [법무] 개인정보 — 후원자 닉네임 · 메시지 포함 여부, 받는 쪽과의 위탁 · 제공 동의
   - [운영] API 인증(키 발급 · 재발급 · 권한 범위)
4. (c)를 한다면
   - [재무] 지급 대행사 선택 · 수수료 부담 주체
   - [운영] 이체 실패 · 재시도 · 중복 지급 방지, 계좌 실명 확인(C6), 보류 중 요청과의 관계

**정해지면 만들 것**: (a) 크루 분배 원장(Earnings와 분리), 멤버 정산 정보, 분배 기록 · 감사 / (b) 내보내기 화면 · API 키 /
(c) 지급 대행 어댑터(멱등 지급 요청 · 결과 웹훅), 지금의 "지급 완료" 수동 기록을 대체.

**기다리는 공통 결정**: C3 · C4 · C5 · C6

## 2. 시그니처 잭팟 (복주머니)

**지금**: 없음. 점수 게임(스핀머신 · 고스톱 등)은 **점수만** 움직이고 FN · 지갑 · 정산은 바꾸지 않습니다.

**StreamDonate에서는**: 기본(슬롯) · 킹스맨(로또) · 복주머니. 복주머니는 시그니처 후원의 일정 비율(그쪽 값 3%)을 풀에 적립하고,
당첨 순번(목표 ±)이 되면 **당첨금이 BJ에게 후원으로 적립**됩니다.

**정해야 할 것**

1. **[제품] [재무] 풀의 돈은 누구 돈인가** — 가장 먼저 정할 것:
   - (A) 후원 금액에서 떼어 냄 — 후원자가 고른 금액보다 크리에이터가 덜 받음, 후원자 고지 필요
   - (B) 플랫폼 수수료에서 부담 — 플랫폼 비용(C3)
   - (C) 실제 돈이 아닌 **점수 풀** — 지금 점수 게임과 같은 방식, 돈은 안 움직임(이 경우 정책 결정 없이 만들 수 있음)
2. [제품] 적립 비율 · 대상(모든 시그니처 / 특정 시그니처 / 금액 구간) — 비율 값은 제안하지 않음
3. [제품] [법무] 당첨 방식 — 정해진 순번 / 목표 ± 범위 / 확률. 확률이 들어가면 확률형 · 사행성 검토(C7)
4. [제품] 당첨금의 성격 — 새 후원(Donation Event)인가, 수익(Earnings) 조정인가:
   - 후원자 랭킹 · 등급 · 칭호에 들어가는지, 알림에 누구 이름으로 나가는지(후원자가 없는 돈)
5. [제품] 받는 사람 — 채널(크리에이터) / 크루 멤버(→ 1번 (a) 크루 분배와 묶임)
6. [제품] [운영] 풀의 수명 — 방송 회차가 끝나거나 수동 초기화할 때 남은 풀(이월 · 반환 · 지급), 적립된 후원이 환불될 때(C8)
7. [제품] 표시 — 후원 페이지 · OBS에 풀 금액 공개, 고지 문구

**정해지면 만들 것**: 풀 원장(적립 · 당첨 · 초기화 각각 기록, 멱등 키 = 후원 id), 당첨 처리 한 번만(동시 후원), 감사 기록,
OBS 연출은 점수 게임 엔진(`crewGameCore`)을 재사용. (C)를 고르면 점수 게임 하나로 바로 만들 수 있음.

**기다리는 공통 결정**: C3 · C7 · C8 (C는 없음)

## 3. 위젯 유료 · 크루 구독

**지금**: 모든 위젯 · 크루 기능이 무료입니다. 크리에이터가 플랫폼에 돈을 내는 흐름(결제 · 청구)이 없습니다.

**StreamDonate에서는**: 위젯 6종은 쓸 때마다 캐시 차감, 크루 기능 22종은 월 구독, 크루 구독이면 위젯 무제한.

**정해야 할 것**

1. [제품] 유료로 할지, **무료 / 유료 목록**(기능 단위), 지금 쓰는 크리에이터의 유예
2. [제품] 과금 방식 — 쓸 때마다(사용량) / 월 구독 / 둘 다, 가격(TBD)
3. [제품] [재무] 무엇으로 내는가:
   - 카드 등 결제(C1 정기결제 필요)
   - FN으로 지불(크리에이터가 FN을 충전 · 보유? C2)
   - 정산금에서 차감(C3 · C4와 엮임, 정산 가능 금액이 모자랄 때)
4. [제품] [법무] 구독 운영 — 자동 갱신 고지, 해지 · 청약철회 · 일할 환불, 결제 실패 시 유예 기간, 해지 · 다운그레이드 후 설정과
   OBS 오버레이가 어떻게 되는지(꺼짐 / 읽기 전용)
5. [제품] 크루 구독 단위 — 채널 하나 / 멤버 수에 따라
6. [재무] 영수증 · 세금계산서(사업자 크리에이터), 부가세(C5)
7. [제품] 무료 체험 · 프로모션 · 미성년 크리에이터(C6)

**정해지면 만들 것**: 기능 권한(entitlement)을 서버에서 판정(화면에서만 막지 않음), 구독 · 청구 원장(FN Wallet과 분리),
정기결제 웹훅 처리(멱등), 만료 · 유예 상태, 크리에이터 청구 내역 화면, 관리자 콘솔 청구 관리.

**기다리는 공통 결정**: C1 · C5 · C7 (+ 3번 선택에 따라 C2 또는 C3 · C4)

## 4. 추천인 · 캐시 선물

**지금**: 없음. FN은 충전한 회원만 쓰고(유상 FN은 환불 정책 대상, 무상 FN은 출석 보상 등), 회원 사이에 FN을 옮기는 기능은 없습니다.

**StreamDonate에서는**: 크리에이터 홈 메뉴에 "추천인 · 캐시 선물" 이름만 확인 — 동작은 보지 못했습니다.

### 4-1. 추천인

1. **[제품] 정의** — 누가 누구를 추천하는가: 크리에이터 → 크리에이터 / 후원자 → 후원자 / 크리에이터 → 후원자
2. [제품] [재무] 보상 — 무상 FN / 수수료 할인 / 일정 기간 수익 배분, 보상 시점(가입 / 첫 충전 / 첫 정산), 1인 상한
3. [운영] [법무] 어뷰징 방지 — 본인인증(C6) · 같은 기기 · 같은 계좌, 자기 추천 차단
4. [제품] 회수 — 추천받은 사람이 탈퇴 · 환불 · 정지될 때 지급한 보상

### 4-2. 캐시 선물

1. **[제품] 정의** — 무엇을 누구에게: 회원이 다른 회원에게 FN 보내기 / 크리에이터가 시청자에게 / 운영자 지급
2. **[법무] 법적 성격** — FN을 양도할 수 있게 되면 선불전자지급수단 · 전자금융거래법 검토 대상이 될 수 있음(C7). 이 결정이 기능
   전체를 좌우
3. [제품] [재무] 받은 FN의 성격 — 유상 / 무상, **환불 가능 여부**(지금 정책: 유상 FN만 환불, 먼저 충전한 것부터 사용),
   보낸 사람이 원래 충전을 환불 · 차지백할 때 이미 보낸 FN
4. [제품] 한도(1회 · 일 · 월), 미성년(C6), 받는 쪽 거절 · 차단, 선물 메시지(금지어)
5. [운영] 사기 · 계정 탈취 대응(선물 보류 · 취소 권한, 감사)

**정해지면 만들 것**: Wallet Transaction 종류 추가(선물 보냄 · 받음, 추천 보상), 보낸 쪽 · 받은 쪽 두 기록을 한 트랜잭션으로(멱등),
환불 계산(`services/wallet/refundCore.ts`)에 선물 FN 반영, 추천 코드 · 링크, 관리자 콘솔 조회 · 회수.

**기다리는 공통 결정**: C2 · C6 · C7 (+ 보상 방식에 따라 C3)

## 5. Direct 후원 수수료

**지금**: "SMS 계좌후원"(목업 어댑터, `/api/bank-sms/[key]`) — 크리에이터 계좌로 바로 들어온 입금 문자에서 금액(원) · 입금자명만
읽어 "계좌 후원" 알림(FN 0)으로 띄우고, 크루 방송 중이면 후원 리스트에 원 단위 "계좌" 항목으로 넣습니다. 돈은 우리 시스템을 거치지
않고 FN · 수익 · 정산과 무관합니다. 수수료는 없습니다.

**StreamDonate에서는**: Direct(계좌) 후원을 받아 알림을 띄웁니다. 수수료 부과 방식은 보지 못했습니다.

**정해야 할 것**

1. [제품] 우리를 거치지 않는 돈에 **수수료를 받을지**
2. 받는다면 [제품] [재무] 방식 — 건별 % / 월 정액 / 위젯 유료 · 크루 구독에 포함(3번과 묶음)
3. [재무] 청구 — 정산금에서 차감(정산할 FN 수익이 없으면?) / 별도 결제(C1) / 선불 충전
4. [제품] [운영] 금액 근거 — 입금 문자는 위조 · 누락 · 중복이 가능하고 개인 거래 입금이 섞일 수 있음. 무엇을 "후원"으로 볼지,
   이의 제기 절차
5. [제품] 후원자 랭킹 · 등급 반영 여부(입금자명으로 회원을 알 수 없음)
6. [법무] 입금자명 개인정보 고지 · 보관 기간 — 지금은 문자 내용 · 계좌번호 · 잔액을 저장하지 않고, 고지 · 보관 · 남용 제한은 TBD
   ([code-first-screens.md](../figma/code-first-screens.md) SMS 계좌후원)

**정해지면 만들 것**: 계좌 후원 원장(지금 알림 기록과 분리), 수수료 청구 원장 · 청구 내역, 문자 검증 · 이의 처리, 정산 차감 연동.

**기다리는 공통 결정**: C3 · C5 (+ 청구 방식에 따라 C1 또는 C4)

## 6. 마이너스 후원

**지금**: 없음. 크루 점수는 방송 중 받은 FN + 보정이고(점수는 돈이 아님), 점수 게임이 점수를 빼는 경우(고스톱 · 스도폴리 칸 점수 등)는 있지만 "후원이 점수를
깎는" 기능은 없습니다. 후원 취소가 들어오는 경로도 없습니다.

**StreamDonate에서는**: 설정에 "마이너스 후원 처리" 이름만 확인 — 동작은 보지 못했습니다.

**정해야 할 것**

1. **[제품] 정의** — 둘 중 무엇인지(둘 다일 수도):
   - (a) **점수를 깎는 후원**: 후원자가 낸 돈은 정상 후원(크리에이터 수익 그대로)인데, 지정한 멤버의 크루 점수가 내려감
   - (b) **취소된 후원의 반영**: 외부 플랫폼 후원 취소 · 우리 후원 환불이 음수 이벤트로 들어올 때 알림 · 점수 · 집계에서 빼기
2. (a)를 한다면
   - [제품] 대상(어떤 후원 · 시그니처), 깎는 양(금액만큼 · 배수), 0 아래 허용 여부
   - [제품] 후원자 쪽 — 낸 금액이 랭킹 · 등급에는 +로 들어가는지
   - [운영] 괴롭힘 · 악용 방지 — 크리에이터 · 크루가 끌 수 있게, 멤버 동의
   - (a)는 돈의 흐름을 바꾸지 않아 점수 게임처럼 만들 수 있지만, **후원 화면에서 "깎기"를 고르게 할지**는 제품 결정
3. (b)를 한다면
   - [제품] [법무] 후원 취소 정책(C8) — 언제 취소되는지, 이미 방송에 나간 알림
   - [제품] 취소된 후원을 크루 점수 · 위젯(목표 · 누적 · 랭킹) · 수단별 보드에서 빼는 시점, 수익 · 정산(이미 정산했으면?)

**정해지면 만들 것**: (a) 후원 기록에 방향(+/−) 추가와 점수 반영(크루 엔진), 후원 화면 선택 / (b) 취소 이벤트 수신(플랫폼
어댑터 매핑, 중복 이벤트 무시), 집계 역반영, 감사 기록.

**기다리는 공통 결정**: (a) 없음(제품 결정만) · (b) C8

## 7. 요약 — 먼저 정하면 가장 많이 풀리는 것

| 항목 | 먼저 정할 것 | 그다음 막는 공통 결정 | 돈 없이 먼저 만들 수 있는 변형 |
|---|---|---|---|
| 외부 정산 연동 | 정의(크루 분배 / 내보내기 / 지급 대행) | C3 · C4 · C5 · C6 | 정산 내역 CSV 내려받기(크리에이터 본인 데이터) — 2026-11-01 만듦 |
| 시그니처 잭팟 복주머니 | 풀의 돈은 누구 돈인가 | C3 · C7 · C8 | 점수 풀(C) — 점수 게임으로 — 2026-11-01 만듦 |
| 위젯 유료 · 크루 구독 | 무료 / 유료 목록 · 과금 방식 | C1 · C5 · C7 | 기능 권한 판정 틀(전부 무료로 둔 채) |
| 추천인 · 캐시 선물 | 정의 + 캐시 선물의 법적 성격 | C2 · C6 · C7 | 없음(보상 · 양도 자체가 돈) |
| Direct 후원 수수료 | 수수료를 받을지 | C3 · C5 | 계좌 후원 원장 분리(수수료 없이) |
| 마이너스 후원 | 정의((a) 점수 / (b) 취소) | (b)만 C8 | (a) 점수를 깎는 후원 — 끌 수 있는 크루 옵션으로 |

공통 결정 중에서는 **C3(수수료 · 수익 배분)**이 다섯 항목을, **C7(법률 검토)**이 세 항목을 막고 있습니다. "돈 없이 먼저 만들 수 있는
변형"은 결정이 아니라 선택지입니다 — 고르면 이 문서의 규칙(돈이 움직이지 않음)을 지키며 먼저 만들 수 있습니다.

결정이 나면 [open-decisions.md](open-decisions.md)에 날짜와 함께 옮기고, 해당 도메인 문서(`docs/domains/*`)를 고친 뒤 구현합니다.
